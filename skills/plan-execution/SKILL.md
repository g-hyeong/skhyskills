# 계획과 실행

현재 요청이 검토·계획·구현·검증 중 무엇인지와 변경 권한부터 구분한다. [승인 기준](references/approval.md)에 따라 사용자가 확정한 범위만 실행하며, 검증만 요청받으면 수정하지 않는다. 프로젝트 공통 discovery·확정 design과 해당 실행 작업의 승인 계획을 [산출물 인계 기준](references/records.md)으로 확인하고 필요한 단계에서 재개한다. 유효한 앞 단계 산출물이 있으면 해당 스킬을 재호출하지 않는다. **아래 세 단계 참조 중 현재 단계 하나만 읽는다.** 단계가 바뀌면 그때 다음 참조를 읽는다. 미리 전부 읽지 않는다.

| 현재 필요한 일 | 읽을 참조 |
| --- | --- |
| 확정 설계의 프로젝트 개발 정책 반영 여부를 확인한 뒤 실제 코드 변경 계획을 작성하고 승인받기 | [계획](references/planning.md) |
| 승인된 실행 계획에 따라 코드·테스트·관련 커밋 진행 | [구현](references/implementation.md) |
| 솔루션·실행 계획과 실제 결과를 대조하고 마무리 | [검증](references/verification.md) |

새 구현에 필요한 솔루션이 정해지지 않았다면 [solution-design](../solution-design/SKILL.md)을 사용한다. 검증만 요청받으면 검증 단계에서 확보된 근거와 누락을 구분한다. 솔루션 승인과 실행 계획 승인은 구분하며, 승인된 같은 범위에서는 승인을 반복하지 않는다. 요구 이해의 문제는 task-discovery, 근본 해결 방향의 문제는 solution-design으로 필요한 피드백만 보내고 산출물 갱신·영향 확인 후 돌아온다. 변경은 사용자 확정 범위에서만 수행한다.

기록이나 인계가 필요할 때 [공통 기록 기준](references/records.md)을 읽는다. 의미 있는 독립 작업의 위임이 유리할 때만 [delegate-work](../delegate-work/SKILL.md)을 사용한다.
