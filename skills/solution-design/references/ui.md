# UI와 컴포넌트

- 새 업무 화면의 첫 구성안에서 과제명과 지표 이름만 바꿔 다른 과제에 그대로 쓸 수 있는지 살핀다. 그렇다면 담당자가 내려야 할 판단이나 취해야 할 행동과 그 근거가 되는 과제 데이터가 먼저 보이도록 배치한다. 이때 과제에서 확인한 데이터와 지정 양식을 따르고, 기존 화면의 부분 수정에는 이 점검을 생략한다.
- 목적에 맞는 한 가지 시각 방향을 정한다. CSS 변수로 색상·간격·모서리·글자 크기를 통일하고 기존 디자인 시스템이 있으면 재사용한다.
- 화면은 공통 기본 컴포넌트와 기능별 컴포넌트로 나눈다. 업무 데이터 조작을 기본 Button·Dialog 등에 넣지 않는다.
- 파생 가능한 값을 별도 상태로 중복 저장하지 않는다. 서버/클라이언트 컴포넌트를 사용하는 스택을 선택했다면 조회·비밀 처리·상호작용에 맞춰 경계를 정한다.
- loading / empty / error / success를 설계한다. 오류 뒤 재시도와 입력 보존, 중복 제출 방지를 고려한다.
- 표·차트에는 단위·기준시각·범례·정렬 기준을 표시한다. 도메인 용어는 필요한 곳에 설명하고 알 수 없는 값과 0을 구분한다.
- 의미 있는 HTML·label·키보드 포커스·명도 대비를 사용한다. 모바일 폭에서도 내용이 잘리지 않게 한다.
- 실제 렌더링·주요 입력·버튼·실패 상태를 확인한다. 스크린샷이 보기 좋은 것과 기능이 동작하는 것을 구분한다.
