# 구조 설계

먼저 기존 구조와 과제의 입출력·실행 환경·제출 조건을 맞춘다. UI, 업무 규칙, 데이터 접근, 외부 연동의 책임과 방향을 정하되 필요 없는 계층을 만들지 않는다. 분석 스크립트·배치·CLI·독립 서버가 맞는 과제에 웹 프레임워크를 강제하지 않는다.

- 데이터가 들어와 검증·변환·업무 판단을 거쳐 결과가 나오는 경로를 설명한다. 외부 응답·파일 형식과 내부 업무 표현을 구분한다.
- 기존 폴더와 모듈을 우선 재사용하고 추가할 책임·인터페이스·상위 폴더의 역할을 정한다. 실제 코드와 파일별 변경 순서는 실행 계획에서 구체화한다.
- 핵심 계산·규칙은 가능한 한 UI·전송·저장소에서 분리해 독립적으로 검사할 수 있게 한다. 한 번 쓰는 코드를 위해 범용 계층·패턴을 만들지 않는다.
- 비밀·권한이 필요한 동작과 외부 입력의 신뢰 경계를 표시한다. 서버·DB·캐시·상태 관리 도입은 실제 요구로 판단한다.
- TypeScript·Next.js 웹 구성을 선택하거나 해당 대안을 구체적으로 비교해야 할 때만 [TypeScript·Next.js 후보](typescript-next.md)를 읽는다. 다른 스택의 세부 사용법은 제공 버전의 공식 자료를 확인한다.
