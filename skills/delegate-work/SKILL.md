# 작업 위임

부모는 사용자 소통·목표·중요 판단·통합을 맡는다. [승인 기준](../plan-execution/references/approval.md)에 따라 확정된 범위만 위임한다. 검토자는 수정하지 않으며 범위 밖 변경은 부모를 통해 사용자에게 질문한다. 시험 규정과 제공 환경의 지침을 우선한다. 과제 이해·설계·계획·구현·검증 어느 단계든 필요한 경우에만 사용하는 보조 스킬이며 별도 필수 단계가 아니다.

1. 독립 작업은 필요한 수만 병렬 배정하고 의존 구간만 순차로 잇는다. 범위가 명확한 긴 작업 하나는 통째로 맡길 수 있다. 짧은 조회·작은 수정·긴밀한 사용자 조율은 직접 처리한다. 단순 조회는 도구 병렬 호출로 충분한지 먼저 판단한다. 인계·중복·실패·충돌 비용이 이익보다 크면 위임하지 않는다.
2. 위임 전에 [대회 모델·호스트 기준](references/hackathon.md)을 읽고 허용된 세 모델 안에서 작업 레벨·실제 모델 ID·지원 추론 수준을 고른다. 선택은 도구 인자에 반영하고 기본/상속 모델도 허용 여부를 확인한다. 확인할 수 없는 모델로 위임하거나 별도 AI API·숨은 옵션으로 우회하지 않는다.
3. 기본은 새 맥락과 최소 지시다. [위임 지시 틀](references/delegation-prompt.md)에서 목표·최신 조건·입력 경로·산출물·완료 기준·읽기/쓰기 범위·권한·Git 담당을 필요한 만큼 전달한다. 최신 승인 결정과 사용자 정정만 실행 기준으로 전달하고 잠정·폐기된 대안은 제외한다. 전체 로그·개인 이력·비밀은 넘기지 않는다. 넓은 맥락이 실제 필요할 때만 대화 상속을 사용한다.
4. 파일별 쓰기 담당을 하나로 정하고 다른 작업자의 변경을 되돌리거나 커밋하지 않는다. 공유 작업 트리의 Git 쓰기는 한 담당자가 순차 처리한다. 자식의 재위임은 기본 금지하며 독립 범위·깊이·슬롯을 부모가 명시한 경우만 허용한다. 재위임도 같은 모델 허용·호스트 한도·쓰기 소유권을 따른다. 독립 구현을 맡은 자식만 [공통 기록 기준](../plan-execution/references/records.md)에 따라 실행 작업 ID를 만든다. 조사·설계 위임은 공통 산출물 담당자에게 결과를 반환하며 별도 작업 폴더를 만들지 않는다. 부모의 현재 단계 파일은 지정 담당자만 갱신한다.
5. 독립 작업은 먼저 배정하고 부모는 같은 일을 반복하지 않는다. 다른 일·사용자 조율·통합 준비를 맡는다. 새 정정은 해당 작업자에게 전달한다. 대기는 지원되는 이벤트 방식으로, 한 번에 60초 이내로 한다. 실패 시 재배정은 [모델 기준](references/hackathon.md)의 해당 절차를 따른다.
6. 반환은 완료한 범위·결론·산출물 위치·실제 검증 근거·남은 문제로 압축한다. 특정 상태 이름이나 보고 양식을 강제하지 않는다. 부모는 원래 완료 조건과 핵심 출처·변경 범위·통합 결과를 대조한다. 필요한 검증만 보충하고 이미 입증된 작업을 전부 재실행하지 않는다. 누락은 기존 작업자에게 먼저 보완 요청한다. 중요한 위험·충돌·편향에는 독립 검토를 사용하며, 검토자에게 기대 답을 주입하지 않는다.

부분 결과·종료·취소는 완료가 아니다. 여러 에이전트의 동의만으로 사실을 확정하지 않는다. 최종 보고에는 실제 결과와 한계만 담고, 측정 없는 시간·토큰 절감률을 주장하지 않는다.
